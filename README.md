# 智能温控风扇系统（STM32F103C8T6 + FreeRTOS）

[![MCU](https://img.shields.io/badge/MCU-STM32F103C8T6-blue)]()
[![RTOS](https://img.shields.io/badge/RTOS-FreeRTOS%20%7C%20CMSIS--RTOS%20v2-green)]()
[![Toolchain](https://img.shields.io/badge/Toolchain-Keil%20MDK5-orange)]()
[![Build](https://img.shields.io/badge/build-0%20Error%200%20Warning-brightgreen)]()

一个基于 STM32F103C8T6 与 FreeRTOS 的智能温控风扇，支持**串口屏 / 蓝牙 / 语音三路控制**、
**增量式 PID 恒温调速**、人体感应自动启停、倒计时、舵机摇头与蜂鸣告警，并配有独立设计的电源与保护电路 PCB。

> 完整的通信协议、命令码表、控件映射与调试步骤见 **[USER_PROTOCOL.md](USER_PROTOCOL.md)**。

## 功能特性

### 控制功能

| 功能 | 说明 |
|---|---|
| 手动模式 | 通过串口屏 / 蓝牙 / 语音自由开关风扇、调节 1~5 档 |
| 自动模式 | `(人体红外有人 或 压力坐下)` **且** `温度 > 阈值` → 自动开启 |
| PID 恒温调速 | 自动模式下以温度阈值为设定值，增量式 PID 动态修正档位 |
| 滞环启停 | 人离开 30s 或温度降到 `阈值−2℃` 以下自动关闭 |
| 倒计时 | 可设 0~3600s，时间到关风扇 + 关摇头 + 舵机回中位 |
| 舵机摇头 | 非阻塞状态机，左右摆头循环，可随时开关 |
| 蜂鸣告警 | 自动模式运行时"滴 200ms / 停 1.8s"循环，30s 后自动静音 |

### 三路异构控制入口

| 入口 | 接口 | 协议 | 命令数 |
|---|---|---|---|
| TJC 串口屏 | USART2 @ 115200 | 自定义帧 `'@' + CMD + VALUE` | 16 |
| HC-05 蓝牙 | USART3 @ 9600 | 文本行协议，回 `ACK:xxx` | 18 |
| SU-03T 语音 | USART1 @ 9600 | 二进制帧 `AA 55 CMD VALUE XOR` | 18 |

三路指令统一抽象为 **17 种命令码**，投递到同一命令队列，由单一控制任务收敛执行，
实现指令源与执行逻辑完全解耦。OLED 与串口屏同步显示运行状态。

## 系统架构

```
                    ┌──────────────────────────────────────────────┐
   TJC 串口屏 ──────▶│ USART2 ─┐                                    │
   (115200)          │         │  ┌──────────┐                      │
                    │         ├─▶│ 环形缓冲 │                      │
   HC-05 蓝牙 ──────▶│ USART3 ─┤  │ (每路256B)│                     │
   (9600)            │         │  └────┬─────┘                      │
                    │         │       │ 协议解析（任务上下文）        │
   SU-03T 语音 ─────▶│ USART1 ─┘       ▼                            │
   (9600)            │          ┌─────────────────┐                 │
                    │          │  xQueueCmd      │ 16 × 8B         │
                    │          │  统一命令队列    │                 │
                    │          └────────┬────────┘                 │
                    │                   ▼                          │
                    │       ┌───────────────────────┐              │
                    │       │  Task_MotorFan (High) │◀── 唯一执行器 │
                    │       │  模式逻辑 / PID 执行   │    写入者     │
                    │       │  倒计时 / 摇头 / 告警 │              │
                    │       └───────────┬───────────┘              │
                    │                   │                          │
                    │   ┌───────────────┼───────────────┐          │
                    │   ▼               ▼               ▼          │
                    │ TB6612 风扇     舵机 PWM       蜂鸣器        │
                    └──────────────────────────────────────────────┘

   传感器侧：                   显示侧：
   DHT11 (PA1) ─┐               ┌─ Task_OLED ──▶ SSD1306 (I2C1)
   红外   (PA0) ─┼─ Task_Sensor ─┤
   压力   (PA5) ─┘   (AboveNormal)└─ xQueueSensorData ──▶ Task_Uart_UI ──▶ TJC 屏
   压力AO (PA4)         │  500ms 周期
                       └── PID 运算 (10s) ──▶ CMD_PID_LEVEL ──▶ xQueueCmd
```

**设计要点**

- **单一执行器写入者**：只有 `Task_MotorFan` 操作硬件外设，其它任务一律通过命令队列请求，消除并发竞争，从头到尾不需要互斥量。
- **字节级数据不进队列**：一条 10 字节的命令如果按字节入队会占 10 个队列项，很容易把队列打满并挤掉真正的控制命令。因此三路串口各配独立环形缓冲，**只有解析完成的命令才入队**。
- **中断只做搬运**：`HAL_UART_RxCpltCallback` 仅做一次写缓冲 + 指针自增，协议解析全部在任务上下文完成，保证 ISR 足够短。

## 任务与内核对象

| 任务 | 优先级 | 栈 | 周期 | 职责 |
|---|---|---|---|---|
| `defaultTask` | Normal | 128 w | 一次性 | 上电初始化（OLED / 传感器 / 协议），完成后 `vTaskSuspend` |
| `Task_MotorFan` | **High** | 128 w | 20 ms 节拍 | 命令消费、模式逻辑、PID 执行、倒计时、摇头、告警 |
| `Task_Sensor` | AboveNormal | 128 w | 20 ms / 500 ms / 10 s | DHT11、红外、压力采集；PID 运算 |
| `Task_Uart_UI` | AboveNormal | 128 w | 20 ms | TJC 串口屏协议解析与状态上报 |
| `Task_Bluetooth` | AboveNormal | 128 w | 20 ms | 蓝牙文本行协议解析 |
| `Task_Voice` | AboveNormal | 128 w | 20 ms | SU-03T 二进制帧解析 |
| `Task_OLED` | Normal | 128 w | 200 ms | OLED 显示刷新 |

| 内核对象 | 配置 | 用途 |
|---|---|---|
| `xQueueCmd` | 16 × 8 B | 统一控制命令队列 |
| `xQueueSensorData` | 8 × 8 B | 传感器数据 → 显示任务 |

> 为压缩 RAM，`SensorMsg_t` 被设计为恰好 8 字节以匹配队列元素大小：
> `temp(1) + humi(1) + flags(1) + level(1) + pressure(2) + reserved(2)`。

## 核心技术点

### 1. 增量式 PID 恒温调速

针对温控对象的特性做了针对性选型：

| 项目 | 取值 | 依据 |
|---|---|---|
| 算法 | **增量式 PID** | Δu = Kp·(e[k]−e[k−1]) + Ki·e[k] + Kd·(e[k]−2e[k−1]+e[k−2]) |
| 设定值 | 当前温度阈值 | 阈值既是启动条件，也是控制目标 |
| 输出 | 风扇档位 1~5 | 限幅，PID 不负责关机 |
| 运算周期 | **10 s** | 温控对象时间常数在分钟级，取 1/10 ~ 1/5 |
| Kp / Ki / Kd | 0.30 / 0.12 / 0.04 | 见 `app_state.h` |
| 死区 | **±0.5 ℃** | DHT11 仅 1 ℃ 分辨率，无死区会稳态抖动 |
| 数值实现 | **全整数定点** | Cortex-M3 无 FPU，规避浮点库的 Flash 与周期开销 |

**为什么用增量式而非位置式**

1. 温控是大惯性对象，执行器是离散档位（1~5）。增量式输出的是"增量"，不会因积分项瞬间累积把执行器一次打到极限；
2. 不需要保存历史积分项，RAM 开销小；
3. 积分作用体现在**已被限幅的** u[k−1] 上，**结构上天然不存在积分饱和**，无需额外的抗饱和逻辑。

**为什么 Kd 取值很小**：DHT11 采样周期 2 s、分辨率 1 ℃，微分项对量化噪声敏感，取值过大会把噪声放大成档位抖动，因此 Kd 仅用于抑制温度突变。

### 2. RAM 受限下的显示与数据方案

- **OLED 页式局部刷新**：放弃常规的 1 KB 全屏显存，改用 128 B 行缓冲 + **脏行比较**，仅重绘内容变化的行，同时减少 I2C 传输量；
- **消息结构体压到 8 字节**：匹配 CubeMX 生成的队列元素大小，避免改动内核对象配置；
- 所有大数组一律全局静态分配，杜绝任务栈溢出与堆碎片。

### 3. 纯时序外设驱动（DHT11）

DHT11 是纯时序器件：主机起始信号需拉低 ≥18 ms，随后传感器应答脉冲仅 **80 µs**，
每个数据位高电平仅 27 µs / 70 µs。因此**起始信号与读取应答必须在同一次连续调用内完成**，
一旦被 RTOS tick 切开，等下一次调度进来时应答早已结束，读取必然失败。

驱动的处理方式：

- 单次连续完成 `18 ms 起始 + 5 ms 读取 40 bit`；
- 仅在读取 40 bit 的 **4 ms** 区间关中断，保证 27/70 µs 判定准确；
- 自带 **2 s 间隔保护**（DHT11 硬件采样上限），未到间隔立即返回；
- 校验前 4 字节之和的低 8 位，校验失败保留上一次有效值，**不写入 0 造成自动模式误判**。

### 4. 无空闲定时器下的微秒延时

TIM4 已被 HAL 用作时基、SysTick 已交由 FreeRTOS，且 SysTick 优先级高于
`configMAX_SYSCALL_INTERRUPT_PRIORITY`，**不可挪作 µs 延时**。
因此改用 Cortex-M3 的 **DWT 周期计数器**实现微秒延时：不占用任何定时器、
不产生中断、精度 1/72 µs。

### 5. 三路异构指令源解耦

- 三路串口各配 **256 B 环形缓冲**，中断里只写缓冲、任务里解析；
- 抽象 **17 种统一命令码**（`cmd.h`），串口屏 / 蓝牙 / 语音的差异只在各自解析层；
- 命令队列满时**丢弃而非阻塞 UI 任务**，并统计丢包数（`g_state.stat.cmd_drop`）；
- 统一的**命令去抖**（200 ms）防止人手连击导致档位飞跳，PID 输出命令则绕过去抖。

### 6. 舵机摇头非阻塞状态机

摇头采用 6 状态有限状态机（左转 / 左停留 / 回中 / 中位停留 / 右转 / 右停留），
不使用任何 `delay`，不影响控制任务节拍；限幅 45°~225° 防止顶到机械限位导致堵转发热。

## 踩坑与修复记录

这一节记录开发过程中定位到的真实问题，其中前三个都是"**编译能过但上板必挂**"的典型陷阱。

### ① FreeRTOS 堆不足导致调度器启动即死锁

CubeMX 默认 `configTOTAL_HEAP_SIZE = 3072`，但实际需求为：

```
7 个任务栈（6×128 w + 定时器守护任务 256 w）  ≈ 3584 B
+ 7 个 TCB + 2 个队列 + 1 个互斥量 + 定时器队列 ≈ 1400 B
合计                                          ≈ 5.0 KB
```

`pvPortMalloc` 返回 `NULL`，内核在 `configASSERT` 中
`taskDISABLE_INTERRUPTS(); for(;;);` 死循环——**现象是"上电像死机，什么都不动"**，
且因为在调度器启动前发生，串口也没有任何输出，极难定位。

**修复**：`configTOTAL_HEAP_SIZE` 由 3072 上调至 **8192**（C8T6 有 20 KB SRAM）。

### ② 位时序被 RTOS tick 切分导致 DHT11 永远读失败

第一版把 DHT11 写成"每 20 ms 推进一个状态机阶段"，编译通过、逻辑看着也合理，
但传感器的应答脉冲只有 80 µs，跨 tick 进入时早已结束，**永远拿不到数据**。

**修复**：改为单次连续完成完整时序（见上文核心技术点 3）。

### ③ 高级定时器缺 MOE 位导致舵机无输出

TIM1 是高级定时器，输出需要 `MOE`（Main Output Enable）置位。
必须通过 `HAL_TIM_PWM_Start()` 启动而非只配置通道，否则 **CCR 写了但引脚没有波形**。

### ④ 1.1 kHz 载波引发直流电机啸叫

TIM3 默认 `PSC=0, ARR=65535` → 约 1.1 kHz，落在人耳可听范围内，
小直流电机会有明显啸叫和低速抖动。

**修复**：`PSC=0, ARR=3599` → **20 kHz**，超出人耳范围，分辨率 3600 级。

### ⑤ 蜂鸣器与舵机的电源冲击

舵机堵转电流 1~2.3 A，与主控共用 USB 5 V 会导致掉压复位。
**修复（硬件）**：舵机独立 5~6 V 供电、与主控共地，信号线单独走 PA8。

### ⑥ 关风扇与倒计时状态不一致

手动关风扇时若不清除倒计时，会出现"风扇已停但倒计时仍在跑、到点又触发一次关机"的怪状态。
**修复**：`Fan_Shutdown()` 统一负责关风扇 + 取消倒计时 + （可选）关摇头回中位，
所有关闭路径都走这一个出口。

### ⑦ 温度量化导致档位稳态抖动

DHT11 分辨率 1 ℃，若目标温度恰落在两个整数之间，误差会在 ±1 之间反复跳变。
**修复**：PID 引入 **±0.5 ℃ 死区**，在目标附近不调节。

2. `Rebuild All`（或按 `F7`）
3. 预期结果：**0 Error, 0 Warning**

```bash
UV4.exe -b MDK-ARM/smart_fan.uvprojx -o build_log.txt
```

使用 ST-Link / J-Link 通过 **SWD** 接口烧录（PA13 = SWDIO，PA14 = SWCLK，
CubeMX 配置已关闭 JTAG、保留 SWD 以释放 PB3/PB4）。

> 也可直接烧录 `MDK-ARM/smart_fan/smart_fan.hex`。

## 快速上手

按顺序测试，每步都有明确成功现象：

| 步骤 | 操作 | 成功现象 | 失败排查 |
|---|---|---|---|
| 1 | 上电 | OLED 显示 4 行状态 | 全黑 → OLED 地址/接线（代码自动试 0x3C 与 0x3D） |
| 2 | 手机连 HC-05，发 `STATUS` | 收到 `ACK:STATUS` | 无回复 → 检查 USART3 交叉接线与 9600 波特率 |
| 3 | 发 `ON` 再发 `L+` | 风扇转动、档位递增、OLED 同步 | 只转不调速 → 检查 PWMA / PB5 |
| 4 | 发 `SWING` | 舵机左右摆头 | 不动 → **先查舵机独立供电与共地**，再查 PA8 |
| 5 | 发 `AUTO`，手靠近红外模块 | 风扇开启 + 蜂鸣告警 | 无响应 → HC-SR501 需约 1 分钟预热 |
| 6 | 串口屏点按钮 | 屏上数值实时刷新 | 不动 → 核对控件名 `t0`~`t7` |
| 7 | 发 `TIME10` | 倒计时递减，到点全部关闭 | — |

**注意**：第 5 步若要让 **PID 恒温调速**真正表现出来，
需要让温度**确实高于**设定阈值（可用热源靠近 DHT11），
且 **DHT11 必须远离风扇出风口**（详见"已知限制"）。

蓝牙命令与串口屏/语音命令的完整列表见 **[USER_PROTOCOL.md](USER_PROTOCOL.md)**。

## 已知限制

1. **PID 恒温效果依赖环境**：直流风扇对封闭房间的整体降温能力有限，PID 的价值体现在
   **抑制温度超调与稳态振荡、按需调速**（而非"把房间吹到某个温度"）。
   演示时建议配合局部热源，使温度可被实际拉低。

2. **DHT11 必须远离出风口**：PID 需要负反馈，测的必须是**环境温度**。
   若传感器位于风道内，风扇加速会使其读数下降，构成**正反馈**，
   PID 会持续加档并饱和到最高档而无法收敛。这是传感器布置问题，不是算法问题。

3. **DHT11 精度限制**：分辨率 1 ℃、采样周期 ≥1 s（代码限制 2 s），
   湿度精度 ±5% RH，不适合高精度温控场合。如需更高精度可换成 SHT30 / AHT20（I2C）。

4. **OLED 中文显示**：当前字库为 8×16 ASCII（95 个字符，3040 字节 Flash）。
   显示中文需扩展 16×16 点阵字库。

5. **无 Flash 参数存储**：阈值等设置掉电不保存。如需保存可扩展片内 Flash 或外挂 EEPROM。

6. **串口屏 UI 需自行搭建**：仓库提供的是单片机侧协议与控件名约定，
   TJC 上位机工程（`.HMI`）需按 `USER_PROTOCOL.md` 中的控件表自行创建。
